# کاوشگر — راهنمای دپلوی روی Railway

این بسته مخصوص دپلوی روی **Railway** است. بخش تحلیلگر هوش مصنوعی با کلید API شخصی شما کار می‌کند و ارتباطش قطع نمی‌شود.

---

## ۱. روش دپلوی (دو راه)

### راه اول — از طریق گیت‌هاب (توصیه‌شده)
1. محتوای این zip را در یک ریپوی گیت‌هاب (خصوصی) آپلود کنید.
2. در [railway.com](https://railway.com) → **New Project** → **Deploy from GitHub repo** → ریپو را انتخاب کنید.
3. Railway خودکار `Dockerfile` را تشخیص می‌دهد و بیلد می‌گیرد (چند دقیقه طول می‌کشد).

### راه دوم — با Railway CLI
```bash
npm i -g @railway/cli
railway login
railway init
railway up        # داخل همین پوشه اجرا شود
```

---

## ۲. ولوم دائمی (مهم‌ترین قدم — داده‌ها حذف نشوند)

بدون ولوم، دیتابیس بعد از هر دپلوی مجدد پاک می‌شود. حتماً ولوم وصل کنید:

1. روی سرویس کلیک کنید → تب **Volumes** (یا Settings → Volumes)
2. **New Volume** → مسیر مانت (Mount Path) را دقیقاً این بگذارید:
   ```
   /data
   ```
3. دپلوی مجدد بگیرید (Redeploy).

اسکریپت راه‌اندازی، ولیوم را خودکار تشخیص می‌دهد (`RAILWAY_VOLUME_MOUNT_PATH`) و دیتابیس، سشن تلگرام، کاربران و پرونده‌ها را آنجا نگه می‌دارد. در اولین اجرا، دیتابیس همراه بسته (شامل **کاربر ادمین 2010/2010 و تنظیمات تلگرام**) به‌صورت خودکار بازگردانی می‌شود.

> اگر عمداً می‌خواهید به دیتابیس اولیه برگردید، در Railway یک Shell باز کنید و فایل `/data/kavoshgar.db` را حذف کنید و دپلوی مجدد بگیرید.

## ۳. متغیرهای محیطی (Variables)

### الف) هوش مصنوعی — برای تحلیلگر (اجباری برای Railway)

بخش تحلیلگر و چت هوشمند به یک سرویس AI سازگار با OpenAI وصل می‌شود. سه متغیر را ست کنید:

| متغیر | مقدار | توضیح |
|---|---|---|
| `AI_API_KEY` | کلید API شما | از پنل سرویس موردنظر بگیرید |
| `AI_BASE_URL` | جدول زیر | آدرس سرویس |
| `AI_MODEL` | جدول زیر | نام مدل |

گزینه‌های آماده:

| سرویس | AI_BASE_URL | AI_MODEL |
|---|---|---|
| **Z.ai (GLM)** — پیش‌فرض | `https://api.z.ai/api/paas/v4` | `glm-4.6` یا `glm-4.5-air` |
| **OpenAI** | `https://api.openai.com/v1` | `gpt-4o-mini` |
| **OpenRouter** | `https://openrouter.ai/api/v1` | هر مدل موجود در OpenRouter |
| **DeepSeek** | `https://api.deepseek.com/v1` | `deepseek-chat` |

> **نکته:** اگر فقط `OPENAI_API_KEY` ست کنید، آدرس OpenAI خودکار فرض می‌شود. اگر هیچ‌کدام ست نشود، تحلیلگر پیام راهنمای فارسی نشان می‌دهد و بقیه ابزار سالم کار می‌کند.

### ب) امنیت سشن (توصیه‌شده)

| متغیر | مقدار |
|---|---|
| `AUTH_SECRET` | یک رشته تصادفی طولانی (مثلاً خروجی `openssl rand -hex 32`) |

با این متغیر، ورود کاربران بعد از دپلوی مجدد هم معتبر می‌ماند.

### ج) کلیدهای اختیاری ماژول‌ها

| متغیر | کاربرد |
|---|---|
| `HIKER_API_KEY` | داده کامل اینستاگرام (بدون آن فقط داده عمومی و ردیاب‌ها) |
| `TRUECALLER_TOKEN` | جستجوی موبایل با تروکالر |
| `GITHUB_TOKEN` | جستجوی گیت‌هاب با نرخ محدودیت بالاتر |

## ۴. دامنه عمومی

1. تب **Settings** → **Networking** → **Generate Domain**
2. یک دامنه مثل `kavoshgar-production.up.railway.app` می‌گیرید — پنل آماده است.

---

## ۵. بعد از دپلوی

1. وارد دامنه شوید → ورود با `2010` / `2010`
2. **فوراً رمز ادمین را از پنل مدیریت عوض کنید** (سرور روی اینترنت عمومی است).
3. تلگرام را از پنل مدیریت ست کنید (API ID/Hash و ورود با کد). سشن تلگرام در دیتابیس روی ولوم ذخیره می‌شود و با دپلوی مجدد نمی‌پرد.
4. بخش تحلیلگر را با یک جستجوی آزمایشی چک کنید — باید گزارش و چت جواب بدهد.

---

## ۶. دیتابیس جستجو (شناسایی اکانت فیسبوک)

باکس «شناسایی اکانت فیسبوک» در صفحه اصلی، هر متن یا عددی را در فایل‌های TXT بارگذاری‌شده جستجو می‌کند و **کل سطرِ حاوی مورد** را نشان می‌دهد.

**راه‌اندازی (فقط یک‌بار):**
1. وارد پنل مدیریت شوید → تب **«دیتابیس جستجو»**
2. فایل‌های TXT دیتابیس را بکشید و رها کنید (چند فایل هم‌زمان، **بدون محدودیت حجم**) — یا متن را در باکس **«افزودن دستی متن»** بچسبانید
3. فایل‌ها روی ولیوم `/data/searchdb/` ذخیره می‌شوند و بین دپلوی‌ها می‌مانند

**نکات:**
- آپلود **تکه‌تکه (۱۶MB)** انجام می‌شود و مقاوم به قطعی شبکه است — اگر وسط آپلود قطع شد، دوباره همان فایل را انتخاب کنید؛ **از محل قطع‌شده ادامه می‌یابد** و بخش‌های کامل‌شده دوباره فرستاده نمی‌شوند
- افزودن دستی دو حالت دارد: **«فایل جدید»** (ساخت/جایگزینی فایل) و **«افزودن به فایل موجود»** (الحاق به انتهای فایل انتخابی با مرز خطِ سالم)
- جستجو استریمی و حافظه‌بهینه است — فایل چندگیگابایتی هم بدون مشکل RAM جستجو می‌شود (معمولاً چند ثانیه)
- ارقام فارسی/عربی خودکار به انگلیسی تبدیل می‌شوند؛ پس جستجوی «۰۹۱۲…» همان «0912…» را می‌یابد
- هر جستجوی کاربران در گزارش جستجوهای پنل ادمین ثبت می‌شود
- حذف فایل از همان تب پنل ادمین انجام می‌شود

## ۷. سوالات پرتکرار

**داده‌ها بعد از چند ساعت حذف می‌شوند؟**
فقط اگر ولوم `/data` وصل نکرده باشید. با ولوم، دیتابیس بین دپلوی‌ها و ری‌استارت‌ها می‌ماند.

**تحلیلگر خطای «موتور هوش مصنوعی در دسترس نیست» می‌دهد؟**
یعنی `AI_API_KEY` ست نشده یا نامعتبر است. Variables را چک کنید و دپلوی مجدد بگیرید.

**بیلد شکست خورد؟**
لاگ بیلد Railway را ببینید. اغلب مشکل کمبود حافظه در بیلد است — در Settings → Build، گزینه افزایش RAM بیلد را فعال کنید یا `NODE_OPTIONS=--max-old-space-size=3072` را به Variables اضافه کنید.

**تلگرام وصل نمی‌شود؟**
Railway خروجی اینترنت کامل دارد؛ فقط مطمئن شوید API ID/Hash درست است و کد ورود را ظرف مهلت تایپ می‌کنید.

## ۸. اجرا با داکر در هر جای دیگر (اختیاری)

```bash
docker build -t kavoshgar .
docker run -p 3000:3000 \
  -e AI_API_KEY=your-key \
  -e AI_BASE_URL=https://api.z.ai/api/paas/v4 \
  -e AI_MODEL=glm-4.6 \
  -v kavoshgar-data:/data \
  kavoshgar
```
